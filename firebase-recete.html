# Görev

Unity ile geliştirilen bu mobil oyuna Firebase tabanlı oyuncu analitiği kur. Aşağıda, canlıda çalışan başka bir projede kurulmuş ve hataları ayıklanmış bir mimari var. Aynı yapıyı bu projeye uyarla.

Önce projeyi incele: hangi Unity sürümü, Firebase SDK kurulu mu, oyun döngüsü nasıl işliyor (level bazlı mı, sonsuz mu), hangi olaylar anlamlı. Sonra aşağıdaki yapıyı projenin kendi terminolojisine uyarlayarak kur.

# Mimari — üç dosya

## 1. FirebaseManager.cs
Firebase Analytics + Crashlytics köprüsü. Singleton, DontDestroyOnLoad.

Sorumlulukları:
- FirebaseApp.CheckAndFixDependenciesAsync() ile init
- Analytics event'lerini göndermek
- Kullanıcı özelliklerini (user property) set etmek
- Uygulama arka plana geçtiğinde/kapandığında oturum sonu kaydı

KRİTİK: Init asenkron. Uygulamanın ilk karesinde tetiklenen olaylar SDK hazır
olmadan gelir. Bunları "if (!isReady) return;" ile atma — kuyruğa al, init
bitince sırayla gönder:

    private readonly List pendingEvents = new List();
    private const int MAX_PENDING_EVENTS = 64;

    private bool Defer(Action action)
    {
        if (isReady) return false;
        if (pendingEvents.Count < MAX_PENDING_EVENTS) pendingEvents.Add(action);
        return true;
    }

    private void MarkReady()
    {
        isReady = true;
        var queued = new List(pendingEvents);
        pendingEvents.Clear();
        foreach (var a in queued)
        {
            try { a(); }
            catch (Exception e) { Debug.LogWarning("[Firebase] " + e.Message); }
        }
    }

Her public Log metodu şu kalıpta olsun:

    public void LogLevelStart(int levelIndex, LevelContext ctx = default)
    {
        // yerel durum SDK'dan bağımsız, HEMEN güncellenir
        activeLevel = levelIndex;
        levelActive = true;

        if (Defer(() => SendLevelStart(levelIndex, ctx))) return;
        SendLevelStart(levelIndex, ctx);
    }

Yerel durumu (aktif level, zaman sayaçları) kuyruğun dışında tut — aksi halde
init sırasında başlayan level "aktif değil" sanılır.

## 2. FirestoreAnalytics.cs
Oyuncu başına derin geçmiş. Analytics'in veremediği kullanıcı bazlı detay burada.

Veri yapısı:
  users/{deviceId}                            → dashboard'un listelediği özet
  users/{deviceId}/meta/profile               → aynı özetin detaylı kopyası
  users/{deviceId}/sessions/{sessionId}       → oturum kayıtları
  users/{deviceId}/level_history/{levelIndex} → level bazlı detay

KRİTİK KURAL 1 — Asla UpdateAsync kullanma, hep SetAsync(MergeAll):

    private void Merge(DocumentReference doc, Dictionary data, string tag)
    {
        doc.SetAsync(data, SetOptions.MergeAll).ContinueWithOnMainThread(task =>
        {
            if (task.IsFaulted)
                Debug.LogWarning("[Firestore] '" + tag + "' yazılamadı: " +
                                 task.Exception?.GetBaseException().Message);
        });
    }

UpdateAsync, hedef doküman yoksa NOT_FOUND fırlatır. Task sonucu kontrol
edilmediği için bu sessizce veri kaybettirir. SetAsync(MergeAll) dokümanı
yoksa oluşturur. FieldValue.Increment ve ArrayUnion merge-set içinde çalışır.

KRİTİK KURAL 2 — Her yazmanın sonucunu logla. Yukarıdaki Merge bunu yapıyor.
Hata loglaması olmadan "veri mi bozuk, ben mi yanlış bakıyorum" sorusunu
cevaplayamazsın.

KRİTİK KURAL 3 — Firestore'dan OKUMA yapma. "En uzak level", "en iyi süre",
"kurulum tarihi" gibi karşılaştırma gerektiren değerleri PlayerPrefs'te yerel
tut, sadece değiştiğinde yaz:

    if (levelIndex > PlayerPrefs.GetInt(PREF_FARTHEST, -1))
    {
        PlayerPrefs.SetInt(PREF_FARTHEST, levelIndex);
        MergeProfileAndRoot(new Dictionary
        {
            { "farthest_level", levelIndex }
        }, "farthest_level");
    }

Bu, level başına 2 okuma + 2 yazmayı tek yazmaya indirir. Firestore ücretsiz
kotası günde 50k okuma / 20k yazma; okuma başına ayrıca ağ gidiş-dönüşü var.

KRİTİK KURAL 4 — Süreleri kırp. Time.realtimeSinceStartup uygulama arka
plandayken de işler. Telefonu cebine koyup bir saat sonra dönen oyuncu o
seviyeye 60 dakika yazdırır:

    private const double MAX_EVENT_SECONDS = 3600;
    private static long SaneSeconds(double s)
    {
        if (double.IsNaN(s) || s <= 0) return 0;
        return (long)Math.Min(s, MAX_EVENT_SECONDS);
    }

Ayrıca OnApplicationPause'da arka planda geçen süreyi sayaçlardan düş.

KRİTİK KURAL 5 — Kısa arka plan kesintisi yeni oturum sayılmasın:

    private const double NEW_SESSION_AFTER_SECONDS = 30;

Bildirim çubuğunu açıp kapatmak yeni oturum sayılırsa oturum sayısı şişer.

## 3. LevelContext.cs
Olay anındaki oynanış bağlamını taşıyan struct. Altı parametreyi tek tek her
metot imzasına eklemek yerine tek yapı hâlinde geçir.

    public struct LevelContext
    {
        public int  levelType;        // mekanik bayrakları
        public int  movesMade;        // bu denemede yapılan hamle
        public int  rotationsUsed;    // mekanik keşfedildi mi
        public int  matchesMade;      // ne kadar yaklaştı
        public int  piecesRemaining;  // olay anındaki durum
        public int  attemptNumber;    // bu levelin kaçıncı denemesi
        public bool tutorialShown;    // tutorial görüldü mü
    }

EN DEĞERLİ ALAN: movesMade. "Oyuncu 8 kez sıfırladı" tek başına bir şey
söylemez. Sıfır hamleyle sıfırladıysa tahtayı ANLAMADI; sekiz hamleyle
sıfırladıysa anladı ama ÇÖZEMEDİ. İkisi farklı problem, farklı çözüm.
Bu ayrımı yapamazsan tasarım kararı veremezsin.

Sayaçları oyun mantığındaki doğal kancalara bağla (başarılı yerleştirme,
döndürme, eşleşme) ve her deneme başında sıfırla.

# Olay şeması

level_start     → level_index, level_type, attempt_number, tutorial_shown
level_complete  → + duration_seconds, moves_made, rotations_used
level_fail      → + moves_made, matches_made, pieces_remaining
level_retry     → + moves_made, matches_made, pieces_remaining
level_reset     → + moves_made, matches_made, rotations_used, pieces_remaining
level_quit      → + duration_seconds, moves_made, pieces_remaining
session_end     → duration_seconds, levels_played

Firestore'a türetilmiş sayaçlar da yaz — dashboard'da hesaplamadan okunsun:
  zero_move_resets, zero_move_fails, zero_move_retries
  total_moves, total_rotations
  last_reset_moves, last_fail_pieces, last_solve_moves

# Firestore güvenlik kuralları

Dashboard alt koleksiyonları toplu okuyacaksa collection group sorgusu gerekir.
"match /users/{document=**}" bunları KAPSAMAZ — her collection group ayrı
kural ister:

    match /{path=**}/meta/{doc}          { allow read: if ; }
    match /{path=**}/sessions/{doc}      { allow read: if ; }
    match /{path=**}/level_history/{doc} { allow read: if ; }

Bu kural yoksa sorgu "Missing or insufficient permissions" ile reddedilir.
Dashboard tarafında collection group'u dene, hata alırsan kullanıcı bazlı
çekmeye düş — böylece kural durumundan bağımsız çalışır.

GÜVENLİK: "allow read, write: if true" ile başlama. En azından silmeyi kapat:

    allow read, create, update: if true;
    allow delete: if false;

Oyun hiçbir zaman silmez; bu tek satır en kötü senaryoyu (verinin silinmesi)
ortadan kaldırır. Kalıcı çözüm anonim auth + kullanıcı bazlı yazma izni.

# BigQuery

Firebase Console → Project Settings → Integrations → BigQuery → Link.
Google Analytics'i seç, Daily export yeter, reklam kimliğini dahil etme.

Bunu PROJENİN BAŞINDA aç — geçmiş veriyi almaz, sadece bağlandıktan sonraki
event'ler akar. Her geciken gün kalıcı veri kaybı.

Ham event'lerde user_pseudo_id bazında DISTINCT sayabilirsin; elle yazılmış
Firestore toplama mantığından çok daha güvenilir. Funnel sorgusu:

    WITH starts AS (
      SELECT
        (SELECT value.int_value FROM UNNEST(event_params)
         WHERE key = 'level_index') AS level_index,
        user_pseudo_id
      FROM `PROJE.analytics_PROPERTY_ID.events_*`
      WHERE _TABLE_SUFFIX BETWEEN '20260101'
                              AND FORMAT_DATE('%Y%m%d', CURRENT_DATE())
        AND event_name = 'level_start'
    ),
    completes AS (
      SELECT
        (SELECT value.int_value FROM UNNEST(event_params)
         WHERE key = 'level_index') AS level_index,
        user_pseudo_id
      FROM `PROJE.analytics_PROPERTY_ID.events_*`
      WHERE _TABLE_SUFFIX BETWEEN '20260101'
                              AND FORMAT_DATE('%Y%m%d', CURRENT_DATE())
        AND event_name = 'level_complete'
    )
    SELECT
      s.level_index + 1 AS level_no,
      COUNT(DISTINCT s.user_pseudo_id) AS ulasan_oyuncu,
      COUNT(DISTINCT c.user_pseudo_id) AS bitiren_oyuncu,
      ROUND(100 * COUNT(DISTINCT c.user_pseudo_id)
                / NULLIF(COUNT(DISTINCT s.user_pseudo_id), 0), 1) AS bitirme_yuzdesi
    FROM starts s
    LEFT JOIN completes c
      ON s.level_index = c.level_index
     AND s.user_pseudo_id = c.user_pseudo_id
    GROUP BY level_no
    ORDER BY level_no

Takılma noktasını bulmak için aynı kalıpla level_reset event'inde moves_made
dağılımına bak — sıfır hamleli reset oranı yüksekse level anlaşılmıyor,
düşükse gerçekten zor:

    SELECT
      (SELECT value.int_value FROM UNNEST(event_params)
       WHERE key = 'level_index') + 1 AS level_no,
      COUNTIF((SELECT value.int_value FROM UNNEST(event_params)
               WHERE key = 'moves_made') = 0) AS sifir_hamleli_reset,
      COUNT(*) AS toplam_reset
    FROM `PROJE.analytics_PROPERTY_ID.events_*`
    WHERE event_name = 'level_reset'
    GROUP BY level_no
    ORDER BY level_no

# Doğrulama

Kod yazdıktan sonra MUTLAKA gerçek cihazda doğrula. Editör tüm asset'lere
erişebilir, build ise sadece referans edilenleri içerir — "editörde çalışıyor,
telefonda çalışmıyor" bu projenin en sık hatasıydı.

    adb shell setprop debug.firebase.analytics.app 

Sonra Firebase Console → Analytics → DebugView. Event'ler 10-20 saniyede akar.

Firestore yazmaları DebugView'de GÖRÜNMEZ, onlar için logcat:

    adb logcat -s Unity:V | grep -i -E "Firestore|Firebase"

Şu satırı görmelisin: "[Firebase] N bekleyen olay gönderiliyor."
Bu, kuyruğun çalıştığının ve ilk level_start'ın kaybolmadığının kanıtıdır.

Prompt'un içindeki altı tuzak

Aşağıdakiler teorik uyarı değil — hepsi ilk projede canlıya çıktı, hiçbiri hata vermedi ve hepsi veri kaybettirdi.

Asenkron init yarışı Her açılışın ilk olayı

CheckAndFixDependenciesAsync() callback'i ilk kareden sonra döner. Start() içinde tetiklenen olay isReady false olduğu için düşer.

Çözüm Olay kuyruğu — hazır olana kadar biriktir, init bitince sırayla gönder.

UpdateAsync sessiz kaybı Doküman yoksa tüm yazma

Hedef doküman yoksa NOT_FOUND fırlatır. Task sonucu kontrol edilmediği için hiçbir yerde görünmez. Yukarıdaki tuzakla birleşince zincirleme kayıp: ilk olay düşer → doküman oluşmaz → sonraki tüm yazmalar da kaybolur.

Çözüm SetAsync(MergeAll) — yoksa oluşturur, varsa birleştirir.

Hata yutma Teşhis imkânsız

Her SetAsync/UpdateAsync sonucu atılıyordu. Kota aşımı, izin hatası, NOT_FOUND — hepsi görünmez.

Çözüm Her yazmada task.IsFaulted kontrolü ve konsol uyarısı.

Okuma-önce-yaz Kota ve gecikme

“En uzak level” ve “en iyi süre” için her level başında Firestore okunuyordu: level başına 2 okuma + 2 yazma, her biri telefonda ağ gidiş-dönüşü.

Çözüm Karşılaştırma değerlerini PlayerPrefs'te tut, yalnızca değişince yaz.

Arka plan süresi Şişmiş oynanış süresi

Time.realtimeSinceStartup uygulama arka plandayken de işler. Telefonu cebine koyan oyuncu o seviyeye saatler yazdırır.

Çözüm OnApplicationPause'da geçen süreyi sayaçlardan düş, ayrıca üst sınırla kırp.

Oturum şişmesi “19 oturum / 2 gün”

Her ön plana dönüş yeni oturum açıyordu. Bildirim çubuğunu açıp kapatmak bile oturum sayılıyordu.

Çözüm 30 saniyeden kısa kesintide aynı oturumu sürdür.
